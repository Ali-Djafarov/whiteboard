# Whiteboard

Live Demo: https://whiteboard-dun-iota.vercel.app/

Откройте приложение в двух вкладках браузера и перейдите по одной и той же ссылке комнаты, чтобы проверить совместную работу.

Совместная онлайн-доска, разработанная на **React, TypeScript, Canvas и Yjs**.


Проект вдохновлён такими инструментами, как Excalidraw, и создан как портфолио-проект для изучения и демонстрации работы с интерактивным Canvas, real-time синхронизацией, управлением состоянием и frontend-архитектурой.

## Возможности

- Бесконечный Canvas с поддержкой pan и zoom
- Масштабируемая сетка
- Создание прямоугольников, текста, рисунков и эллипсов
- Выделение элементов
- Множественное выделение
- Перемещение и изменение размера элементов
- Выделение области с помощью marquee
- Стрелки, текст и свободное рисование
- Undo / Redo
- Совместное редактирование в реальном времени
- Комнаты по ссылке
- Курсоры других пользователей с именами и цветами
- Горячие клавиши
- Управление масштабом
- Деплой frontend и WebSocket-сервера

## Совместная работа

Каждая доска имеет собственный ID комнаты, который хранится в URL.

Например:

```text
https://your-app.vercel.app/#a8f31c2d
```

Если несколько пользователей открывают одну и ту же ссылку, они подключаются к одной комнате и видят изменения друг друга в реальном времени.

Для этого используются:

- **Yjs** — общее состояние документа
- **y-websocket** — синхронизация между клиентами
- **Y.UndoManager** — Undo / Redo локальных изменений
- **Yjs Awareness** — информация о пользователях и их курсорах

Обновления курсоров ограничены по частоте, чтобы не создавать лишнюю нагрузку на WebSocket-соединение.

### Архитектура

Проект построен с использованием принципов **Feature-Sliced Design**.

Основные слои:

```text
app/
pages/
widgets/
features/
entities/
shared/
```

Логика разделена между:

- моделью сцены
- Canvas-рендерингом
- viewport и преобразованиями координат
- инструментами рисования
- выделением и взаимодействием с элементами
- collaboration
- UI-компонентами
- общими утилитами

Это позволяет изолировать бизнес-логику сцены от специфичной для collaboration функциональности.

## Архитектурные решения

### Canvas вместо DOM/SVG

Для доски используется Canvas API.

Canvas позволяет напрямую контролировать:

- рендеринг элементов
- pan и zoom
- преобразование координат
- выделение
- сетку
- пользовательское рисование

Сцена и её визуальное представление разделены между собой.

### Yjs для совместного состояния

Сцена представляет собой общий изменяемый документ, поэтому для синхронизации используется Yjs.

Вместо самостоятельной реализации разрешения конфликтов изменения синхронизируются через Yjs.

При этом локальные и удалённые изменения используют одну модель данных.

### Отдельный viewport

Координаты элементов сцены не зависят от положения и масштаба камеры.

Viewport содержит:

```text
offsetX
offsetY
zoom
```

Преобразования между screen coordinates и world coordinates вынесены в отдельную логику.

Благодаря этому одна и та же сцена корректно отображается при любом масштабе и положении камеры.

### Collaboration как отдельная фича

курсоры других пользователей отображаются отдельным UI-слоем поверх Canvas.

Это позволяет не смешивать логику сцены с логикой совместной работы.

## Запуск локально

Установить зависимости:

```bash
npm ci
```

Запустить frontend и WebSocket-сервер:

```bash
npm run dev
```

Frontend будет доступен по адресу:

```text
http://localhost:5173
```

WebSocket-сервер:

```text
ws://localhost:1234
```

## Переменные окружения

Для production frontend использует URL WebSocket-сервера:

```env
VITE_WS_URL=wss://your-websocket-server.example.com
```

При локальном запуске по умолчанию используется:

```text
ws://localhost:1234
```

## Деплой

Frontend размещён на **Vercel**.

WebSocket-сервер размещён на **Render**.

Архитектура production-окружения:

```text
Браузер
   │
   ├── HTTPS ──────────► Vercel
   │                     React + Canvas
   │
   └── WebSocket ──────► Render
                          Yjs WebSocket Server
```

### Важно: первый запуск сервера может занять время

WebSocket-сервер размещён на бесплатном тарифе Render.

После периода бездействия сервер может перейти в спящий режим. При первом подключении после простоя ему может потребоваться **до минуты на запуск**.

Поэтому после открытия приложения иногда может потребоваться немного подождать, прежде чем установится WebSocket-соединение и станет доступна совместная работа.

Это ограничение бесплатного хостинга Render, а не ошибка приложения.
